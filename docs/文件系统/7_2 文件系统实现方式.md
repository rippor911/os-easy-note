## 文件控制块

我们在进程管理中使用PCB来保存进程的管理信息。为了更好的管理物理文件，我们同样需要有类似的文件控制块

**组成：**

+ 基本信息：文件名、物理位置、逻辑结构、物理结构
+ 访问控制信息：文件所有者（属主）、访问权限
+ 使用信息：创建时间、上一次修改时间、当前使用信息等

例如MOS中：

```c
struct File {
	char f_name[MAXNAMELEN]; // filename
	uint32_t f_size;	 // file size in bytes
	uint32_t f_type;	 // file type
	uint32_t f_direct[NDIRECT];
	uint32_t f_indirect;

	struct File *f_dir; // the pointer to the dir where this file is in, valid only in memory.
	char f_pad[FILE_STRUCT_SIZE - MAXNAMELEN - (3 + NDIRECT) * 4 - sizeof(void *)];
} __attribute__((aligned(4), packed));
```

文件逻辑结构（文件组织）：提高检索效率，便于修改，降低文件存储代价

+ 假设一个文件被分成N块，如何在磁盘上存放？

### 文件物理结构

#### 连续（顺序）结构

#### 串联/链接文件结构

![image-20260611100841274](C:/Users/rippor/AppData/Roaming/Typora/typora-user-images/image-20260611100841274.png)

![image-20260611102724461](C:/Users/rippor/AppData/Roaming/Typora/typora-user-images/image-20260611102724461.png)

每个物理块存一个链接字，指向后继块的物理地址

若要存取 Ri ，需要从 R0 起依次通过链接遍历直到访问Ri

#### 索引结构

![image-20260611100924196](C:/Users/rippor/AppData/Roaming/Typora/typora-user-images/image-20260611100924196.png)

每个文件有一个索引表，索引表存放物理块号

索引表应该放在磁盘上，即一个文件在磁盘上的存储区包括：索引区+数据区

**访问索引文件的步骤**

1. 读取文件索引区，由逻辑块号查到物理块号
2. 访问物理块号获得所需信息

**【典例】**读取Linux下`/tmp/hello`的过程（假定根目录`inode`已在内存中）

+ 读取根目录内容，获得`tmp`目录的`inode`所在的物理块号

+ 读取`tmp`的`inode`信息，获得`tmp`目录项所在的物理块号

+ 读取`tmp`目录内容，获得hello的`inode`所在的物理块号

+ 读取`hello`的`inode`信息，获得`hello`的物理块号。

+ 读取`hello`的数据

**索引表的组织：**

+ 链接模式：一个盘块一个索引表，多个索引表链接起来
+ 索引方式：
  + 直接索引
  + 间接索引：将一个大文件的所有索引表（二级索引）放在另一个索引表（一级索引）中
  + 综合直接和间接

#### 总结对比

| 结构 |                  核心                  |                             优点                             |                             缺点                             |
| :--: | :------------------------------------: | :----------------------------------------------------------: | :----------------------------------------------------------: |
| 连续 | 在磁盘上连续存放<br>适合变化不大的文件 | 简单易实现<br>不需要额外空间开销<br>顺序存取和随机存取效率高 | 文件长度不易改变<br>不利于文件的动态增删 <br>容易产生磁盘碎片 |
| 链接 |           用链接字指向下一块           | 外存空间利用率高<br>文件动态扩充和修改容易<br>顺序存取效率高 | 随机存取效率低<br>可靠性问题，如指针出错<br>链接指针占用一定空间 |
| 索引 |  用索引表实现逻辑块号到物理块号的映射  |             保留链接结构优点<br>避免连接结构缺点             |                    带来空间开销和时间开销                    |

## 目录的实现

![image-20260611105836662](C:/Users/rippor/AppData/Roaming/Typora/typora-user-images/image-20260611105836662.png)

**一般实现方式：**

+ 直接法：目录项=文件名+文件控制块
+ 间接法：目录项=文件名+文件控制块的地址或索引号

### 处理长文件名的方法

+ 文件名固定长度为255个字符。缺点是长文件名文件较少，浪费空间
+ 目录项文件名长度可变。缺点是文件删除后难以回收利用
+ 目录项本身长度固定，把长度可变的文件名统一放在目录文件末尾

### 文件目录查询技术

+ 顺序查寻法：依次扫描，逐个比对name
+ Hash法：把name映射成索引

### 便于共享的目录组织

![image-20260611110352505](C:/Users/rippor/AppData/Roaming/Typora/typora-user-images/image-20260611110352505.png)

**文件共享：**

- **硬连接：** 多个目录项**指向同一个索引节点**（`inode`）。删除其中一个文件名不会影响其他硬连接，只有所有硬连接都被删除后，文件数据才会被释放；通常不能跨文件系统，也不能链接目录。
- **软连接：** 创建一个新的特殊文件，其中**保存目标文件的路径**。可以跨文件系统，也可以链接目录；若目标文件被删除或移动，软连接会失效。

> [!TIP]
>
> 硬连接→同一个文件的另一个名字
>
> 软连接→文件系统层面的快捷方式

## 一致性问题

有两类一致性：

+ 磁盘块的一致性：每个磁盘块设置两个计数器，块在文件中和在空闲队列中出现次数应一致
+ 文件的一致性：每个文件设置两个计数器，`inode`被引用次数和文件目录引用该文件的次数应一致

**文件的并发访问：**

+ 访问文件之前必须先打开文件：
  + 若不在内存，从外存读入
  + 否则，使用已在内存的目录内容
  + 避免反复读取相同元数据，实现文件一致性
+ 利用进程间通信协调对文件的访问

## 文件系统性能问题

**主要瓶颈：**磁盘服务

→应尽可能减少磁盘访问次数

**具体方法：** 

目录项分解、当前目录、磁盘碎片整理、**块高速缓存**、磁盘调度、提前读取、合理分配磁盘空间、数据的优化分布、RAID技术等。

### 块高速缓存

**核心：**在内存中为磁盘块设置一个缓冲区，保存磁盘某些块的副本

+ 当发生读请求时，检查是否在块高速缓存中
  + 若在，直接进行读
  + 若不在，先把数据块读入块高速缓存
+ 组织方式：块高速缓存可用双向链表组织若干个数据块，用散列提高检查速度
+ 置换策略
+ 写入策略：需要考虑一致性问题

### 基于日志结构的文件系统（LFS）

**问题引入：**写操作性能提升困难，磁头的寻道是影响磁盘写性能的主要因素之一

**基本思路：把大量零散的随机写，合并成一次较大的顺序写**

+ 修改内容（数据块、inode、目录等）先以segment为单位放在缓存中
+ segment满后再整体顺序写入磁盘末尾
+ 旧版本不进行覆盖，只是将最新inode指向最新的数据块

**如何找到inode：**imap，实现从inode号到最新inode所在磁盘位置的映射

**旧数据处理：**垃圾回收（garbage collection）

**崩溃恢复：**

+ Checkpoint：周期性保存 imap 各部分所在位置等关键状态
+ Roll-forward：崩溃后从最近的 checkpoint 开始，检查后续日志并恢复有效更新

**优点：**

- 把随机写转化为顺序写；
- 大量小写、创建和删除文件时性能较好；
- 崩溃恢复较快。

**缺点：**

- 需要垃圾回收；
- 磁盘剩余空间少时，清理成本很高；
- 数据更新很随机时，垃圾分散在许多 segment 中，清理开销变大。

### 文件物理结构推荐

针对以下三种用户需求，请推荐最适合的文件物理结构（连续文件 / 链接文件 / 索引文件），并解释原因：

1. 文件系统的性能主要取决于对大文件的**连续访问**。
2. 文件系统的性能主要取决于对大文件的**随机访问**。
3. 提高**磁盘空间利用率**是文件系统的主要目标。

<Reveal title="答案解析">

1. **连续文件结构**：大文件在磁盘上连续存放，顺序访问只需一次寻道，读写效率极高。

2. **索引文件结构**：通过索引表可以直接定位到任意数据块的位置，无需遍历链表，随机访问效率最高。

3. **链接文件结构**：不要求连续磁盘空间，可以充分利用零散的空闲块，磁盘空间利用率最高。

来源：2025 期末考试，九。
