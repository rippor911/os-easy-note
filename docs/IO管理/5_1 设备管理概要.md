## 设备的管理概要

### 我们为什么需要设备管理？

I/O性能经常成为系统性能的瓶颈，OS复杂的主要原因就是资源多、杂、并发，而I/O占大头：

+ 速度差异很大
+ 控制接口复杂
+ 传输单位不同
+ 数据表示各异
+ 错误条件多样

**外设管理目的：** 

+ 提效（I/O访问效率，匹配CPU和外设处理速度）
+ 便利（逻辑I/O+驱动隐藏细节，方便用户）
+ 可控（可增删设备，可适用于新设备类型）

我们需要设备管理，正如当初我们需要内存管理。

> [!NOTE]
>
> **外设管理功能：**
>
> + 提供方便、统一且独立于设备的用户接口
> + 根据用户请求控制设备，完成数据交换
> + 管理设备提高性能
>   + I/O缓冲和调度：目标是提高I/O访问效率
>   + 设备分配与回收
>   + 设备访问与控制
> + 保护设备传送、管理的数据

### 我们如何管理I/O？

> [!NOTE]
>
> **I/O基本流程**
>
> 用户提出I/O请求→请求被OS接受→OS设置控制器（包含控制、状态、数据寄存器）→I/O设备进入处理阶段→返回处理结果

我们结合MOS代码来看看，以下是对设备操作接口的抽象：

```c
struct Dev {
	int dev_id;
	char *dev_name;
	int (*dev_read)(struct Fd *, void *, u_int, u_int);
	int (*dev_write)(struct Fd *, const void *, u_int, u_int);
	int (*dev_close)(struct Fd *);
	int (*dev_stat)(struct Fd *, struct Stat *);
	int (*dev_seek)(struct Fd *, u_int);
};
```

包括：

+ 标识（id、name）
+ 设备驱动程序（读写程序）
+ 中断服务程序（接受中断信号后读取设备状态、处理完成结果、唤醒等待进程等）

便于上层通过统一的接口调用不同的设备驱动程序。

### I/O设备的分类

**按数据组织分类：**

- 块设备：以数据块为单位存储、传输信息。传输速率较高，可寻址（随机读写）
- 字符设备：以字符为单位存储、传输信息。传输速率低，不可寻址。

**按用途分类：**

- 存储设备：磁盘、磁带；
- 传输设备：网卡、Modem；
- 人机交互设备：显示器、键盘、鼠标。

**从资源分配角度：**

- **独占设备**：在一段时间内只能由一个进程使用的设备。通常独占设备的传输速率比较慢，打印机和磁带机都属于典型的独占设备。
- **共享设备**：在一段时间内允许多个进程共同使用的设备。多个进程以交叉的方式来使用设备。资源利用率较高。硬盘是典型的共享设备。
- **虚设备**：在一类设备上模拟另一类设备，常用的方法是，用共享设备模拟独占设备，用高速设备模拟低速设备。如：用Spooling技术将打印机变成共享设备。
