> [!NOTE]
>
> **主引导记录（MBR）：**是计算机硬盘的第一个扇区中存储的特殊数据结构，主要用于存储启动信息和分区表（DPT）。

分区表一个分区的信息包含：

+ Partition flag：引导标志
+ Start CHS：本分区的起始磁头号、扇区号、柱面号
+ Partition Byte：分区类型符
+ End CHS：本分区的结束磁头号、扇区号、柱面号
+ Start LBA：本分区之前已经使用的扇区数
+ Size：本分区的总扇区数

### CHS 模式

> [!NOTE]
>
> **CHS 模式：** 用柱面（Cylinder）、磁头（Head）、扇区（Sector）寻址的模式

某设备的 CHS 分布为：第1个字节为起始磁头号，第2个字节的低6位为起始扇区号，高2位为起始柱面号的高2位，第3字节为起始柱面号的低8位

请计算存储容量大小。

柱面号：$2^{10}$

扇区号：$2^6-1$

磁头号：$2^8$

总容量：$2^{10}\times(2^{6}-1)\times2^8\times 512B\approx 8.46GB$

注意第一个扇区预留作为 MBR

### LBA 模式

> [!NOTE]
>
> **LBA（Logic Block Address）模式：**将磁盘驱动器可以看作一个一维的逻辑块数组，逻辑块是最小传输单位

---

### 两种模式之间的转换

若已知C、H和S，则逻辑地址为：
$$
LBA=(C\times NH\times NS)+(H\times NS)+(S-1)
$$
可以当作是一个**三维数组**

已知 LBA，那么C、H、S分别为：
$$
C=⌊\frac{LBA}{(NS\times NH)}⌋\\
H = ⌊\frac{LBA}{NS}⌋\mod NH\\
S = (LBA\mod NS)+1
$$
实际上核心公式是CHS转LBA，写出核心公式后转回CHS就顺理成章了

## 磁盘空间的管理

> [!NOTE]
>
> 管理方法主要包含：
>
> + 位图：用一串二进制位反应磁盘空间中分配使用情况

## 磁盘调度

### 磁盘性能分析指标

Response Time（磁盘延迟）= Queue（排队等待时间）+ Disk Service Time（磁盘访问时间）

**磁盘访问时间=寻道时间+旋转延迟时间+传输时间**

+ **寻道时间：**把磁头从当前位置移动到指定磁道上经历的时间
  + $T_s=m\times n + s$，$s$ 为启动磁盘时间，$m$ 是移动 1 条磁道花费时间
+ **旋转延迟时间：**旋转到对应扇区经历的时间
  + 若已知转速，可求平均旋转延迟时间（可用转半圈时间计算）
  + $\bar T_r = \frac{1}{2r}$
+ **传输时间：**将数据读出磁盘或写入磁盘经历的时间
  + $T_t=\frac{b}{rN}$
  + $b$ 为单次读/写的字节数，$r$ 为转速，$N$ 为磁道上的字节数
  + 常见 $b$  为 512B，$r\in [60RPS,250RPS]$
  + 典型传输速度为 2MB/s ~ 50MB/s

总访问时间$T_a=T_s+\bar T_r +  T_t$

---

### 磁盘调度算法

通常情况下：收到IO请求速度＞磁盘实际能执行的速度

因此如何按一定顺序高效处理积压的请求，是可以优化的部分

|                              |                             核心                             |         优点         | 缺点                                   |
| :--------------------------: | :----------------------------------------------------------: | :------------------: | -------------------------------------- |
|      先来先服务（FCFS）      |                           先来后到                           |      简单，公平      | 效率不高，折返跑严重；对机械部件有损伤 |
| 最短寻道时间优先算法（SSTF） |                       贪心，最近先解决                       |   改善平均服务时间   | 可能造成“饥饿”                         |
|       扫描算法（SCAN）       |      磁头按一个方向移动，顺路捎带，直到最外（内）侧回头      |    克服SSTF的缺点    | 两侧访问频率仍低于中间                 |
|    循环扫描算法（C-SCAN）    | 磁头只按一个方向移动，顺路捎带，到达最后一个柱面后磁头快速返回起始柱面（过程耗时忽略不计） | 消除对两端磁道不公平 | 端侧无请求时浪费时间扫描（SCAN共性）   |

可将SCAN系算法优化为LOOK算法：即**只需要到最远端的请求即可，不需要到磁盘端点**

**磁臂黏着现象：**对某一磁道有较高的访问频率，从而垄断了整个磁盘设备

**优化：**

+ N-Step-SCAN：队列之间用FCFS，队列内部采用SCAN
+ FSCAN：2-Step-SCAN

## 提高I/O速度的主要途径

+ 选择性能好的磁盘
+ 并行化
+ 采用适当的调度算法
+ 设置磁盘高速缓冲区

### 磁盘高速缓存

形式：

+ 独立缓存（固定大小）
+ 以虚拟内存为缓存（弹性大小）

数据交付：

+ 直接交付（copy开销）
+ 指针交付（内存管理复杂）

置换算法：通常用LRU

周期性写回

### 优化数据布局

+ 优化物理块分布：连续摆放，使得磁头移动距离最小
+ 优化索引节点的分布：访问文件时，先访问索引节点，再去访问盘块，分组使得索引节点盘块与存放文件盘块间距离最小

### 其他方法

+ 提前读：顺序访问时，常采用提前读入下一块到缓冲区
+ 延迟写：直到重新分配时才写回磁盘（可能有可靠性问题）
+ 虚拟盘：利用内存空间去仿真磁盘（RAM盘）

## 复习题

### 磁盘读取时间计算

某磁盘的平均寻道时间是 10 ms，旋转速度为 7500 rpm（转/分钟），每磁道可存储 32KB。该磁盘上文件系统的数据块大小是 4KB，文件的平均大小也是 4KB。若不考虑读取文件控制块和目录的时间，从该磁盘中读取一个文件的平均时间为多少 ms？

<Reveal title="答案解析">

**步骤 1：计算平均旋转延迟**

转速 7500 rpm → 每秒 7500/60 = 125 转。

平均旋转延迟 = 转半圈的时间 = 0.5 / 125 = 0.004 s = **4 ms**

**步骤 2：计算传输时间**

每磁道 32KB，每个文件 4KB → 文件占 1 个数据块。

每转时间 = 60/7500 = 0.008 s = 8 ms。

传输 4KB 占磁道比例 = 4KB / 32KB = 1/8。

传输时间 = (1/8) × 8 ms = **1 ms**

**步骤 3：总访问时间**

T = 平均寻道时间 + 平均旋转延迟 + 传输时间

= 10 ms + 4 ms + 1 ms = **15 ms**

来源：2025 期末考试，六。

</Reveal>
