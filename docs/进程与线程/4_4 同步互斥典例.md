### 生产者-消费者问题

**问题描述：** 若干进程通过有限的共享缓冲区交换数据。其中，“生产者”进程不断写入，而“消费者”进程不断读出；共享缓冲区共有N个；任何时刻只能有一个进程可对共享缓冲区进行操作。

**实例：** 寿司流水席

### 读者－写者问题

**问题描述：**对共享资源的读写操作，任一时刻“写者”最多只允许一个，而“读者”则允许多个。即“读－写”互斥，“写－写”互斥，“读－读”允许。

**实例：**学校选课系统、12306定票

**读者有利算法：**

+ 写者开始后，不允许其他写者、读者进入，直到结束
+ 写者必须在写之前没有正在读的读者和其他写者
+ 读者开始读后，允许其他读者进入，不允许写者进入，直到没有读者才允许写者进入

### PV 操作竞态分析

多个线程共享访问变量 x（初值为 0），使用互斥信号量 mutex（初值为 1）实现同步：

```
P(mutex);
if (x == 0) {
    V(mutex);
    P(mutex);
    x++;
}
V(mutex);
```

请分析：该代码是否保证了线程对变量 x 的互斥访问？x 的取值是否可能大于 1？

<Reveal title="答案解析">

**该代码没有保证互斥访问。**

分析如下：
1. 线程 A 进入：P(mutex)，检测到 x==0，执行 V(mutex) 释放锁
2. 在线程 A 执行 V(mutex) 和 P(mutex) 之间，线程 B 可能获得锁
3. 线程 B 也检测到 x==0，同样执行 V(mutex) 释放锁
4. 结果两个线程都执行了 x++，x 可能变为 2

**关键问题：** 在 V(mutex) 和 P(mutex) 之间存在竞态窗口期。释放锁后重新获取之前，其他线程可能进入临界区。

**x 的取值可能大于 1**，取决于有多少线程通过竞态窗口进入。

来源：2025 期末考试，八-1。

</Reveal>

### 屏障同步设计

N 个线程需要在某个执行点汇合后再并发执行。除信号量外不允许使用任何共享变量。请用 PV 操作设计 `Barrier(int threadID)` 函数。

<Reveal title="答案解析">

**信号量定义：**
```
semaphore arrive[N] = {0, 0, ..., 0};  // N 个信号量，初值均为 0
```

**实现思路：** 线程 i 到达后，通知下一个线程，然后等待自己的信号量。

```
void Barrier(int threadID) {
    int next = (threadID + 1) % N;
    signal(arrive[next]);    // 通知下一个线程：我已到达
    wait(arrive[threadID]);  // 等待上一个线程通知我
}
```

**原理：** 
- 线程 0 先到达，signal(arrive[1])，然后 wait(arrive[0]) 阻塞
- 线程 1 到达，signal(arrive[2])，然后 wait(arrive[1]) 被线程 0 唤醒
- …
- 最后一个线程 N-1 到达，signal(arrive[0]) 唤醒线程 0
- 线程 0 被唤醒后完成 Barrier

这样就形成了一个"信号传递链"，所有线程都到达后才全部释放。

来源：2025 期末考试，八-2。

</Reveal>
