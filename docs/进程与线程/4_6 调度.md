## 调度基础

**调度：**控制协调多个进程对CPU的竞争

WHAT→按什么原则选择下一个执行的进程→进程调度算法

WHEN→进程调度的时机

HOW→CPU切换过程（进程的上下文切换）

**调度类型：**

+ 高级调度：又称宏观调度、作业调度，即从用户角度一次提交若干个作业，对作业进行调度
+ 中级调度：又称内外存交换，将当前所需部分换入内存，若空间不够时把暂时不需要的换出到外存
+ 低级调度：又称微观调度、进程或线程调度，调度进程对CPU的控制权

### 调度评价指标

**调度的性能准则：**

+ 面向用户：周转时间、响应时间、截止时间、优先级、公平性等
+ 面向系统：吞吐量、处理机利用率、各种资源的均衡利用
+ 面向算法：易于实现、开销较小

> [!NOTE]
> 吞吐量 = $\frac{作业数}{总执行时间}$，即单位时间 CPU 完成的作业数量
>
> 周转时间（Turnaround Time）= 完成时刻 - 提交时刻
>
> 带权周转时间 = $\frac{周转时间}{服务时间（执行时间）}$
>
> 平均周转时间 = $\frac{作业周转时间之和}{作业数}$
>
> 平均带权周转时间 = $\frac{作业带权周转时间之和}{作业数}$

> [!CAUTION]
> 多道作业并发时，吞吐量并不等于平均周转时间的倒数，因为多个作业的运行时间可能相互重叠。

## 批处理系统中的调度算法

[调度评价指标](#调度评价指标)

### 先来先服务（FCFS：First Come First Serve）

**核心：** 按变成就绪状态的时间先后调度

**特点：**

+ 利于长作业
+ 利于 CPU Bound

### 短作业优先（SJF：Shortest Job First）

**核心：** 对预计执行时间短的作业优先分派，后来的短作业不抢占正在执行的作业

**优点：**

+ 减少平均周转时间和平均带权周转时间，缩短作业等待时间
+ 提高系统吞吐量

**缺点：**

+ 对长作业不利

### 最短剩余时间优先（SRTF：Shortest Remaining Time First）

**核心：** 将 SJF 改进为抢占式

**缺点：** 源源不断地短任务到来会使长任务“饥饿”

### 最高响应比优先（HRRF：High Response Ratio First）

**核心：** FCFS 和 SJF 的折衷，每次选择作业时（**非抢占式**），计算相应比 $R$ ，选最大进行

$$R = (作业已等待时间+作业的服务时间)/作业的服务时间 = 1 + 作业已等待时间/作业的服务时间 $$

**优点：** 既照顾短作业又不使长作业等待时间过长

**缺点：** 每次计算各道作业的响应比会有一定的时间开销，性能比 SJF 略差。

## 交互式系统的调度算法

[调度评价指标](#调度评价指标)

### 时间片轮转（RR：Round Robin）

**核心：** 当需要调度时（抢占式），将系统中所有的就绪进程按照 FCFS 原则调度，并分配时间片。当时间片用完时，会发生时钟中断

> [!TIP]
>
> **时间片长度的确定**
>
> 长 → 切换开销小，响应慢，退化成 FCFS
>
> 短 → 响应快，但上下文切换开销大
>
> 就绪进程的数目：数目越多，时间片越小
>
> 系统的处理能力：应当使用户输入通常在一个时间片内能处理完；
> 否则会使响应时间、平均周转时间和平均带权周转时间延长。

### 优先级

#### 优先级算法(Priority Scheduling)

可以用多个调度队列区分优先级，先从优先级高的调度

本算法是平衡各进程对响应时间的要求。适用于作业调度和进程调度，可分成抢先式和非抢先式；

**静态优先级：**

创建进程时就确定，直到进程终止前都不改变。通常是一个整数。依据：

+ 进程类型（系统进程优先级较高）
+ 对资源的需求（对CPU和内存需求较少的进程，优先级较高）
+ 用户要求（紧迫程度和付费多少）

**动态优先级：**

+ 在就绪队列中，等待时间延长则优先级提高，从而使优先级较低的进程在等待足够的时间后，其优先级提高到可被调度执行；
+ 进程每执行一个时间片，就降低其优先级，从而一个进程持续执行时，其优先级降低到让出CPU。

#### 优先级反转问题

高优先级进程（或线程）被低优先级进程（或线程）延迟或阻塞。

![优先级反转示例](D:\Desktop\myblog\subwebsite\better-os-note\docs\进程与线程\image-9.png)

#### 解决方法1：优先级置顶

**核心：** 低优先级进程进入临界区后，就临时提高至最高优先级，不允许被抢占

**问题：** 低优先级占有临界区过长时，也会阻碍高优先级进行

#### 解决方法2：优先级继承

**核心：** 当高优先级进程要进入临界区使用临界资源时，如果已有一个低优先级进程使用同样的临界资源，则让该低优先级进程继承高优先级

### 多级队列（MQ：Multi-level Queue）

按照进程类型将进程永久划分到不同的就绪队列，例如系统进程、交互进程和批处理进程。不同队列可以采用不同的调度算法，队列之间还需要规定固定优先级或时间片分配策略。

### 多级反馈队列（MFQ： Multi-level Feedback Queue）

**核心：**

+ 设置不同优先级队列，每个队列执行时间片的长度也不同，规定优先级越低则时间片越长
+ 新进程进入内存后，先投入队列 1 的末尾，按 FCFS 算法调度
+ 若进程在当前队列一个时间片未能执行完，则降低优先级，直到最低则按 RR 调度
+ 抢占式，即优先级高的抢占式调度

**优点：**

+ 为提高系统吞吐量和缩短平均周转时间而照顾短进程
+ 为获得较好的I/O设备利用率和缩短响应时间而照顾I/O型进程
+ 不必估计进程的执行时间，动态调节

为适应一个进程在不同时间段的运行特点，I/O完成时，提高优先级；时间片用完时，降低优先级；

## 实时系统的调度算法

> [!IMPORTANT]
> **实时系统**
>
> **时间主导：** 外部设备发出信号后，要在确定的时间范围内做出恰当反应（周期性）
>
> **分类：** 硬实时系统（必须在时间限制内完成）、软实时系统（可以偶尔不满足）

**问题描述：** 

假设一任务集 $S={t_1,t_2,t_3,..., t_n}$，周期分别是 $T1,T2,...,Tn$ ，执行时间为 $c_1,c_2,..., c_n$，截止周期(deadline)为 $D_1,D_2,..., D_n$，通常 $D_i = T_i$。CPU利用率：
$$U = \sum\limits^n_{i=1} \frac{c_i}{T_i}$$ 

**前提条件**
• 任务集（S）是已知的；
• 所有任务都是周期性（T）的，必须在限定的时限 D 内完成；
• 任务之间都是独立的，每个任务不依赖于其他任务；
• 每个任务的运行时间（c）是不变的；
• 调度, 任务切换的时间忽略不计。

### 静态表调度算法（Static table-driven scheduling）

**核心：** 事先确定调度顺序

**特点：**
• 无任何计算，按固定方案进行，开销最小；
• 无灵活性，只适用于完全固定的任务场景。

### 单调速率调度（RMS：Rate Monotonic Scheduling）

**核心：** 

+ 任务的周期越小，其优先级越高，优先级最高的任务最先被调度
+ 如果两个任务的优先级一样，当调度它们时，RM算法将随机选择一个调度
+ 静态、抢占式调度

**优点：** RMS已被证明是静态最优调度算法, 开销小, 灵活性好, 是实时调度的基础性理论。

**可调度的充分条件：**

$$U = \sum\limits^n_{i=1} \frac{c_i}{T_i} \le n(2^{\frac{1}{n} } - 1)$$

### 最早截止时间优先算法（EDF：Earliest Deadline First）

**核心：** 绝对截止时间越早，其优先级越高（动态）

**可调度的充要条件：**

$$U = \sum\limits^n_{i=1} \frac{c_i}{T_i} \le 1$$

### 最低松弛度优先算法 LLF（Least Laxity First）

**核心：** 任务的紧急度越高，其优先级越高，并使之优先执行。具体来说，根据下面公式计算松弛度，根据优先级**抢占式调度**

`松弛度（Laxity）= 任务截止时间 - 本身剩余运行时间 - 当前时间`

**可调度的充要条件：**

$$U = \sum\limits^n_{i=1} \frac{c_i}{T_i} \le 1$$

## 多处理机调度

**多处理机情境下的特点：**

+ 注重系统整体的性能
+ 更多样的调度算法
+ 多处理机访问共享文件系统的互斥问题
+ 调度单位广泛使用线程

### 非对称式多处理系统AMP（Asymmetric Multi-Processor）

**核心：**各处理机地位不同。主-从处理及系统中，由主处理机管理一个公共就绪队列，分派进程给处理及执行

**特点：** 

+ 可将特定类型的进程分配给固定分工处理机
+ 主机故障则系统崩溃，有潜在的不可靠性

### 对称式多处理系统SMP（Symmetric Multi-Processor）

**控制方式：**

+ 集中控制
  + 静态调度：每个CPU设立一个就绪队列，进程从开始执行到完成在同一个CPU上
    + 优点：算法开销小
    + 缺点：容易出现忙闲不均
  + 动态调度：采用一个公共就绪队列，队首进程分派到当前空闲CPU上
+ 分散控制
  + 自调度：采用一个公共就绪队列，每个处理机可自行选适当进程执行
    + 需要对就绪队列的数据结构进行互斥访问控制
    + 优点：不需要专门处理机从事分派工作
    + 缺点：处理机个数较多时，互斥访问可能成为系统瓶颈
